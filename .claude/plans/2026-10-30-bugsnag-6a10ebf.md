## Root cause

Two external incidents, and no sweep defect. Bugsnag shows the group as "rejected" only because that was the latest event. Both groups hash on `UsdcSweepOperation.swift:run()` / `sweepUntilConverted(...)` (`UsdcSweepOperation.swift:97`, `:170`).
1. **Sep 9 22:00Z – Sep 10 18:00Z: 65 `ErrorStatelessSwap.signatureError` events** on 2026.8.5/9.1, plus the single `6aa2eaa` event. Coinbase migrated the Stable Swapper authority on-chain, so the instruction account lists in shipped builds stopped matching. Coinbase then rolled the migration back (`159434301`, which reverted `22dabe4a2`). There have been none since.
2. **Oct 16 02:46–03:00Z: 8 `ErrorFetchBalance.rejected` events** on 2026.10.2. In the same events, every other service also failed with `rejected`, including the unauthenticated user-flags call. That points to a backend-wide refusal window, not a sweep fault.

## Evidence

- nserror split: signatureError 65 error (Sep 9–10) · rejected 8 error (Oct 16) · transactionFailed 1 info (Oct 2)
- log `[2026-09-10 10:35:27] ERROR swap-service.stateless`: "Stateless swap stream error code=signatureError detailCount=1 reasons=[]"
- `159434301` message: "Coinbase rolled back the authority migration on-chain, so the client change that followed it no longer matches the deployed program"
- log `[2026-10-16 08:59:42] ERROR session-auth`: "Failed to check for unusable account error=rejected", followed at the same second by "USDC sweep failed error=rejected". 7 of 8 events also show feed, blocklist and history failures with `rejected`.
- `TransportClassifiableError.swift:29` collapses 8 gRPC codes into `.rejected` (`RPCError+Extensions.swift:26-27`), so the event can't say which code the server sent.

## Proposed direction

Mark both groups fixed with a comment: "external: Coinbase authority migration rolled back Sep 10 (159434301); Oct 16 backend-wide rejection window". Mark-fixed reopens only on a version newer than the last one seen, so a recurrence on 10.3+ will surface. Optionally carry the underlying `RPCError.code` in the capture metadata for `.rejected`, so the next incident names its code.

## Risk

None for closing. The metadata change touches every `TransportClassifiableError` capture, but only adds a key.
