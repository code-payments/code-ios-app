## Root cause

`SQLITE_PROTOCOL` (15) is SQLite giving up on a WAL read after losing the lock race 100 times, about 10 s of backoff that `busyTimeout = 2` (`Database.swift:88`) doesn't cap (upstream `wal.c`, `walTryBeginRead`). Both failing pushes took 11.34 s, a normal 1–2 s cycle plus that backoff. `isBusy` matches only `SQLITE_BUSY` (`ExtensionStore.swift:98-104`), so the error lands in `.failed` (`ExtensionStore.swift:86-89`) and is reported (`NotificationService.swift:449-453`). Who held the lock is unverified: the app is the file's only other opener (`DatabaseStore.swift:78`), and pushes sent while it is foregrounded, backgrounding (`AppDelegate.swift:176-196`), or suspended would show which state stalls.

## Evidence

- exception — `failed("locking protocol (code: 15)")`, `app.id` `com.flipcash.app.ios.NotificationService`, `thermalState` `serious`
- breadcrumbs — `[16:06:35.252] didReceive` → error `16:06:46.588`; `[16:06:47.217] didReceive` → event `16:06:58.555`; the 30 earlier `didReceive` → `store write: wrote` pairs took 1.0–2.1 s

## Proposed direction

Count `SQLITE_PROTOCOL` as contention in `isBusy`, renamed to match, and reword the docs that tie `.busy` to the write lock (`ExtensionStore.swift:34`, `NotificationService.swift:441-443`). The error then takes the existing contention path, a `store write: busy` breadcrumb instead of a report, which leaves the fetch to the app (`ExtensionStore.swift:82-83`).

## Verification

`FlipcashTests/Regressions/Regression_6ab3f91758142669ea6cc93f.swift`: `ExtensionStore.perform` with a body that throws `SQLite.Result.error(message: "locking protocol", code: SQLITE_PROTOCOL, statement: nil)` returns `.busy` (`.failed` before the fix). Throw it directly; a real one needs a 10 s lost race. `SQLITE_CORRUPT` still returns `.failed`, and `busyLockGivesUp` (`ExtensionStoreTests.swift:248`) stays green.

## Risk

Only reporting changes. Banners still wait out the stall because the write precedes `deliver()` (`NotificationService.swift:359-364`), and repeat stalls will show only as breadcrumbs.
