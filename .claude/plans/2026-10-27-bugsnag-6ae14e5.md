## Root cause

Saving a photo from the chat media viewer crashes whenever the viewer holds the photo's original library-image bytes (`PhotoLibrary.swift:44`). The change block at `PhotoLibrary.swift:31-33` is a non-`Sendable` closure formed inside `enum PhotoLibrary`. The app target defaults to `@MainActor` isolation (`face31082`), so the closure is main-actor isolated, and Swift 6 checks the executor when it runs. Photos runs the block on its own queue (frame `-[PHPhotoLibrary _performCancellableChanges:…onExecutionContext:]`), so the check traps. The older `write(image:)` path doesn't crash because it is `nonisolated` (`PhotoLibrary.swift:14`).

## Evidence

- stack: `__dispatch_assert_queue_fail` ← `swift_task_isCurrentExecutorWithFlagsImpl` ← `closure #1 in static PhotoLibrary.save(originalData:)` ← `PHPhotoLibrary _performCancellableChanges…_block_invoke`, on a `__dispatch_workloop_worker_thread`
- `PhotoLibrary.swift:31` — `try await PHPhotoLibrary.shared().performChanges {`
- `ConversationScreen.swift:563` — `onSave: { image, original in try await PhotoLibrary.save(image: image, original: original) }`
- log `[21:22:22] INFO flipcash.conversation-controller` — `Loaded conversation messages … count=47`, the user was in a chat about 12s before the crash
- `git log` — `c141bfcfb` (10-25, #1133) added `save(originalData:)`. That is the only `performChanges` call in the app.
- `PhotoLibrarySaveTests.swift:29` stubs `writeOriginal`, so the real change block never ran under test

## Proposed direction

Mark the change block passed to `performChanges` as an explicit `@Sendable` closure (`{ @Sendable in … }`) capturing only `data`. A synchronous `@Sendable` closure is nonisolated, so Photos' queue no longer fails the main-actor check.

## Verification

When skipped, the `@Sendable` annotation remains the compile-level guard. Observed failing on the unfixed code as a test-host crash. ## Expert input

- **/simplify**: narrowed the trigger to "original bytes present" (it traps before Photos accepts anything). The factory seam was dropped during the fix: a Swift-side seam never crosses the `@preconcurrency` boundary that emits the executor check, so it passed on the unfixed code; the test calls the real API with permission granted instead.

- **swiftui-specialist**: no SwiftUI change needed, and `onSave` (`ConversationScreen.swift:563`) correctly stays main-actor. Write the block as an explicit `@Sendable` closure capturing only `data`. Don't just mark `save(originalData:)` `nonisolated`: with approachable concurrency on, that makes it `nonisolated(nonsending)`, and the block's isolation would then depend on inference.
- **modernize-tests**: exit tests aren't available on iOS, so the pre-fix trap aborts the whole host run. Run only the regression suite for the "fails first" check. Don't add `@MainActor` to the test, or the block would pass on the unfixed code.
