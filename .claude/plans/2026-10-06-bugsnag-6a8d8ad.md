## Leading hypothesis

SwiftUI sizes a nav-bar title-slot (`.principal`) item in a host whose environment has no `Container`. The read fails in `UIKitBarItemHost.initializeSize()` under `-[_UINavigationBarTitleControl _ensureNecessaryViews]`. That runs from `setNavigationBarHidden:animated:` inside `_UIHostingView.didMoveToWindow`, so a hosting view is joining the window and toggling bar visibility. Both events share that stack. The view that does the read is **not identified**. No View struct in any title-slot item declares `@Environment(Container.self)`, and the inline reads resolve during the parent screen's `body`. In the 2026.10.2 event, the trigger was the same chat pushed three times in one second.

## Evidence

- crash thread 0 — `EnvironmentValues.subscript.getter` ← `ToolbarItemMinimumWidthLayout.sizeThatFits` ← `UIKitBarItemHost.willMove(toSuperview:)` ← `_UINavigationBarTitleControl updateConstraints` ← `UINavigationController setNavigationBarHidden:animated:` ← `_UIHostingView.didMoveToWindow`
- log `20:07:18 flipcash.router` — `Path changed externally stack=tips` (back to the chat list)
- log `20:07:27 flipcash.router` — `Push destination=tipConversation payload=9c3482…` **×3**, then `Set visible conversation … source=onAppear` ×2; crash at 20:07:28.4
- `AppRouter.swift:141` — `push` appends unconditionally, with no check against the current top
- `TipConversationsScreen.swift:90` — the row is a plain `Button` → `router.push(.tipConversation(conversation.id))`
- `PushController.swift:285` — `willPresent` only presents the banner; the pushes came from taps
- Aug 25 event: same stack and no app logs. Breadcrumbs show rapid background/foreground cycling and no visible push, so its trigger is unknown.

## Proposed direction

There are two separate problems. The duplicate push is a real defect on its own: without the crash, the user lands three identical chats deep. The fix is router-level: `push` ignores a destination equal to the one it last appended to that stack, and that record is cleared when the path shrinks. Because `paths` is a `NavigationPath`, the router has to keep its own last-destination record per stack; the existing "Path changed externally" hook covers clearing. A router-level fix covers all 16 `.tipConversation` call sites. The shared bar-item mechanism is still open: reproduce rapid row taps and a background/foreground cycle during a push on iOS 26.6 before changing anything in the toolbar.
