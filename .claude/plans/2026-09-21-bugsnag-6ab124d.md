## Root cause

A misclassified transient, not an upload defect. TLS to S3 closed mid-POST → `_kCFStreamErrorCodeKey=-9816` (`errSSLClosedNoNotify`, `SecBase.h:823`) → `URLError(-1200)` → `BlobUploader` wraps it as `ErrorBlob.network` (`BlobUploader.swift:129`) → which defers to `URLError.reportingLevel` (`BlobService.swift:167-169`) → whose transient list omits `.secureConnectionFailed` (`URLError+Extensions.swift:15-17`) → falls to `else { .error }` (`URLError+Extensions.swift:38`) → ships at error severity (`ErrorReporting.swift:98-107`). The predicted `.error` matches the event's observed `severity: "error"` — the chain closes on output, not just on code.

A second, independent defect compounds it: the call site raises a hard failure dialog the next line without `userFacing: true` (`ProfilePhotoScreen.swift:189-190`). So fixing only the classifier flips this from *pages noisily* to *invisible* — `.suppressed` + `userFacing: false` is dropped outright (`ErrorReporting.swift:22-27`). **Both must land together.**

## Evidence

- nserror.domain — `Code=-1200 … UserInfo={_kCFStreamErrorCodeKey=-9816 … _NSURLErrorNWPathKey=satisfied … LQM: good}`: the OS path was up; the TLS session itself was severed.
- nserror.userInfo — `location=ProfilePhotoScreen.swift:upload():189` pins the throw site.
- Logs: blob reserved `12:36:14` (283KB); 30s later, mid-body, `Upload transport failed … Code=-1200`. Logged INFO locally (`ProfilePhotoScreen.swift:188`), shipped as `severity: error`.
- `TransportClassificationTests.swift:166-181` — seven `URLError` cases, none TLS: untested, not deliberate.
- `NewPublicGroupScreen.swift:363-366` — identical shape, so group-picture upload has the same bug.
- `ErrorReportingOutcomeTests.swift:39-48` pins the "`#545` shape" — a transient reaching a dialog floors to `.info`. That fix landed on the RPC side, never on the blob path.

## Proposed direction

Two changes, together.

1. **Classify the TLS drop without blanket-suppressing `-1200`** — the same envelope carries real trust failures (`-9807`, `-9814`; `SecBase.h:814,821`). Branch in `URLError.reportingLevel` on `errorUserInfo["_kCFStreamErrorCodeKey"]`, suppressing only connection-drop codes and defaulting **explicitly to `.error` when the key is absent or unrecognized**. Leave `URLError.Code.isTransientNetworkError` alone so its documented mirror with `RPCError.Code` (`URLError+Extensions.swift:10-11`) stays exact — userInfo lives on `URLError`, not `Code`.
2. **Pass `userFacing: true`** at both catch sites (`ProfilePhotoScreen.swift:189`, `NewPublicGroupScreen.swift:365`).

## Risk

Low — reporting-only: it cannot change trust evaluation or failure behavior, and the dialog is unaffected. ATS misconfiguration surfaces as `-1022`, outside this path. Residual: a wrong split could quiet a genuine TLS regression, mitigated by the default-to-`.error` fallback.
